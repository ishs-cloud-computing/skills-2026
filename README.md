## 대회 구조

- 1·2과제만 사전 공개되며 이 중에서 출제된다. **3과제는 비공개**이므로 다루지 않는다.
- **1과제**: 단일 과제. 보통 단일 리전 종합 인프라.
- **2과제**: 독립 모듈 여러 개로 구성. 모듈 수와 리전은 세트마다 다르다.
- 각 세트의 구체적인 서비스 구성은 해당 세트의 README나 과제지를 참고한다.

## 디렉토리 구조

```
skills-2026/
├── set-01/ ~ set-10/        # set-08 제외, 모두 동일 구조
│   ├── task-1/              # 단일 과제
│   │   ├── terraform/       # AWS 리소스
│   │   ├── eksctl/          # 클러스터/노드그룹 (EKS 과제일 때만)
│   │   ├── k8s/             # k8s 리소스 (번호 prefix로 apply 순서)
│   │   ├── app/             # 컨테이너 소스 (필요할 때만)
│   │   ├── task.pdf         # 과제지
│   │   ├── mark.pdf         # 채점지
│   │   └── mark.sh          # 채점 스크립트
│   └── task-2/              # 독립 모듈 여러 개
│       ├── module-1/        # 모듈별로 terraform/ eksctl/ k8s/ app/ 중 필요한 것만
│       ├── module-2/
│       └── ...              # 모듈 수는 세트마다 다름
├── shared/
│   ├── modules/             # 재사용 Terraform 모듈 (vpc, eks 등)
│   └── scripts/
└── .github/                 # 세트 트래킹용 이슈 / PR 템플릿
```

하위 디렉토리(`terraform/`, `eksctl/`, `k8s/`, `app/`)는 **해당 과제에 필요한 것만** 만든다.
모든 과제가 EKS나 컨테이너를 쓰는 것은 아니다.

## 진행 상황 관리

- 세트당 부모 이슈 1개([세트 트래킹 템플릿](.github/ISSUE_TEMPLATE/set-tracking.yml))를 만들고,
  실제 작업은 1과제 / 2과제 모듈별 **서브 이슈**로 분리한다.
- 세트·과제 단위로 **브랜치를 분리**한다.
- 위 진행 상황 표는 작업이 진행될 때마다 갱신한다.
