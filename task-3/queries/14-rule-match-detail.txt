# [조사 3단계] 룰 매칭 상세 — 특정 룰이 실제로 무엇에 매칭했는지 원문(matchedData·args) 확인.
# 언제: 02에서 급증한 룰, 04에서 승격 검토 중인 Count 룰을 판정할 때.
# 입력: {{target_rule}} (저장 쿼리 파라미터. 연습 시 예시: "Block-SQLi-In-Args", "AWS-AWSManagedRulesSQLiRuleSet")
# 다음: 매칭 대상이 정상 트래픽 형태면 15(오탐 후보), 공격 확정이면 03/11로 소스 추적.
filter terminatingRuleId = {{target_rule}} or nonTerminatingMatchingRules.0.ruleId = {{target_rule}}
| fields @timestamp, action, terminatingRuleMatchDetails.0.conditionType, terminatingRuleMatchDetails.0.location, httpRequest.httpMethod, httpRequest.uri, httpRequest.args
| sort @timestamp desc
| limit 50
