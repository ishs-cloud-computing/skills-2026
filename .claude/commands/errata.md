# 입력
- `errata/*.txt` — 정본. 변경 내용의 유일한 출처
- `changelog.txt` — 배경, 수정없음 판정, `주의:` 항목
- 대상: $ARGUMENTS

# 완료 상태
errata의 **모든** 항목이 아래 셋 중 하나로 판정되고 근거가 남아 있을 것.

- `영향없음` — 현재 구현이 이미 부합. 근거는 파일 경로 + 해당 부분
- `수정완료` — 패치 적용. 변경한 파일 목록
- `미반영` — 반영하지 않은 이유

추가로:
- NOTES.md의 채점항목 커버리지 표가 갱신되어 있을 것
- `terraform validate` / `terraform plan` 이 깨지지 않을 것
- changelog의 `주의:` 항목은 전부 개별 판정이 있을 것

"확인했습니다"만 있고 근거 경로가 없는 판정은 미완료로 간주한다.

# Phase 1 — 분석 (병렬, 읽기 전용)

세 subagent를 동시에 돌린다. 이 단계에서 파일을 수정하지 않는다.

- **A. errata 정규화**
  항목별로 `{번호, 대상(과제지/채점지/채점스크립트/제공파일), 영향 채점항목, 구현 변경 필요 Y/N}`
  대상이 채점지·채점스크립트뿐이면 구현 변경은 원칙적으로 N이다.
- **B. 구현 인벤토리**
  `terraform/`, `eksctl/`, `k8s/`, `app/`, 런북에서 채점항목 ↔ 리소스 매핑을 만든다.
- **C. 불일치 추출**
  changelog의 `주의:` 항목만 뽑는다. 답변 문구와 errata가 어긋난 지점이라 별도로 다룬다.

A × B 교차표를 출력하고 **멈춘다.** 승인 전에는 Phase 2로 넘어가지 않는다.

# Phase 2 — 패치 (순차, 단일 에이전트)

교차표에서 `수정 필요`로 승인된 항목만 처리한다. 항목 하나당 커밋 하나.
같은 파일을 여러 항목이 건드리면 순서를 먼저 정하고 진행한다.

# Phase 3 — 검증

채점 스크립트를 기준으로 대조한다. errata에 정정본이 있으면 그쪽을 쓴다.
`주의:` 항목은 errata 문구가 아니라 **채점 스크립트의 실제 동작**으로 판단한다.

# 규칙

- `provided/`와 `errata/` 모두 수정 금지.
  단 2과제 Module 4 1)의 Dockerfile은 errata가 지시한 예외
- errata에 없는 개선은 하지 않는다. 범위 밖 제안은 별도 목록으로만 남긴다
- 과제가 요구하지 않은 리소스를 만들지 않는다
- 판정을 바꿀 때는 근거를 함께 남긴다
